# Partline · поиск автозапчастей

Клиентский прототип для Favorit Parts: артикул → производитель → складские предложения и аналоги. React, JavaScript, Redux Toolkit, Vite, Fetch API, обычный CSS.

## Запуск

Требуется Node.js 22.12+ (или 24 LTS).

```sh
npm ci
cp .env.example .env.local
npm run dev
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env.local`. Откройте адрес, который напечатает Vite.

## Подключение API

В `.env.local` задайте:

```dotenv
FAVORIT_API_KEY=ваш_ключ_покупателя
```

Перезапустите Vite. Первый запрос содержит только `number` из поисковых параметров; второй — `number`, `brand`, `analogues=on`. Служебный `key` добавляет Vite proxy. `URLSearchParams` кодирует спецсимволы артикула и бренда.

Документация: [Favorit Parts Web-сервис «Проценка»](https://lk.favorit-parts.ru/static/wsprice.pdf). Endpoint: `http://api.favorit-parts.ru/hs/hsprice/`.

Реальный API дополнительно проверен 26.10.2026 с ключом из примера документации: поиск `01089`, выбор `OSSCA`, получение вложенных аналогов и складских предложений STELLOX. Доступность этого ключа и ответы сервиса могут меняться; один из повторных запросов завершился таймаутом. Для своей проверки задайте действующий ключ в `.env.local`. Ключ не попадает в клиентскую сборку и не коммитится; `.env.local` исключён из Git.

### CORS и публикация

Локальный Vite proxy направляет `/api/parts` на HTTP API, обходя браузерный CORS. Это возможность сервера разработки, не отдельный backend. В статической production-сборке proxy отсутствует. Работа API на HTTPS-хостинге потребует HTTPS reverse proxy на стороне хостинга; прямой HTTP-запрос будет блокироваться как mixed content. Не публикуйте ключ в переменной `VITE_*`.

## Устройство

```text
src/
  api/          # Fetch, проверка ответа, нормализация
  store/        # Один partsSlice и два createAsyncThunk
  components/   # Поиск, бренды, таблица, загрузка, ошибки
  App.jsx       # Debounce и отмена запросов
```

- Debounce 450 мс. Пустой или пробельный артикул не отправляется.
- При изменении артикула выбранный бренд и предложения сбрасываются сразу.
- Thunk `.abort()` передаёт AbortSignal в Fetch (AbortController управляется Redux Toolkit). Дополнительно `requestId` защищает от устаревших ответов.
- Обрабатываются `goods: [{}]`, `goods: {}`, API `error`, квота, HTTP, некорректный JSON и сетевые ошибки. Есть кнопка повторной попытки.
- Корневые товары и их вложенные `analogues` превращаются в строки: один `warehouse` — одно предложение. Цена и остаток берутся **только из `warehouses[].price` и `warehouses[].stock`**. Верхнеуровневые `price` и `count` игнорируются. Нулевой остаток сохраняется, отсутствующая цена показывается как `—`. Дубли одного предложения убираются.
- Адаптивная вёрстка, подписи полей, фокус клавиатуры, статусы для скринридеров; на телефоне таблица прокручивается внутри карточки.

## Проверки

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Модульные проверки: контракт запросов, ошибки, вложенные аналоги, склады, отмена и гонки запросов. Браузерные: debounce, основной сценарий, повторный поиск, ошибки, пустые состояния и мобильная ширина. CI запускает все проверки.
